# Análise Competitiva

## Quando usar
- Entrar em mercado novo, decidir posicionamento, entender por que perde deal para concorrente, priorizar feature baseada em gap competitivo

## Passos
1. Defina o conjunto de concorrentes relevante (direto, substituto, "fazer nada"/planilha) — não liste todo mundo do setor.
2. Critérios objetivos de comparação (preço, funcionalidade core, integrações, SLA) — evite lista subjetiva de "impressões".
3. Fontes primárias quando possível: trial do produto, docs públicas, reviews (G2/Capterra), calls perdidas com motivo registrado.
4. Distinga feature parity de vantagem real — copiar feature sem copiar o porquê raramente move agulha.
5. Traduza gaps em decisão: build, ignorar (não é diferencial pro nosso cliente), ou reposicionar mensagem.
6. Atualize periodicamente — snapshot de concorrência fica velho rápido; date a análise.
7. Compartilhe com vendas/CS para calibrar objection handling, não só como doc interno de produto.

## Armadilhas
- Feature race reativa: buildar tudo que o concorrente lança sem julgar valor pro seu cliente.
- Análise baseada só em marketing do concorrente, não no produto real.
- Documento que nunca mais é atualizado depois do primeiro trimestre.

## Verificação
- Decisões (build/ignore/reposicionar) rastreáveis à análise; doc tem data e é revisitado; time de vendas usa os gaps documentados.
